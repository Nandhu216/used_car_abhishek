Used Car Marketplace System
1. PROJECT OVERVIEW

Project Title: Used Car Marketplace System
Tech Stack: MERN (MongoDB, Express, React, Node.js)

The Used Car Marketplace System is a web-based application that connects Buyers and Sellers of used cars on a centralized digital platform. The system allows sellers to list vehicles, buyers to search and purchase cars, participate in bidding, choose installment payment options, and select delivery methods. The platform ensures transparency, secure transactions, and administrative monitoring.

2. PROBLEM STATEMENT

Currently, used car buying and selling is mostly done through dealers, social media, or classified advertisements.

Problems faced by Buyers:

Lack of accurate vehicle information.

No structured bidding system.

No installment payment option.

Risk of hidden damages.

No delivery support.

Problems faced by Sellers:

Difficulty reaching genuine buyers.

Dependence on middlemen with high commissions.

No proper system to manage enquiries and bids.

No automated price suggestion system.

There is no centralized platform integrating listing management, bidding, EMI payments, delivery tracking, and damage-based price negotiation.

3. PROPOSED SOLUTION

The proposed system is a full-featured online Used Car Marketplace where:

Sellers can register and list cars with images and specifications.

Buyers can search, filter, compare, and save cars.

Buyers can place bids on auction-enabled vehicles.

Buyers can choose Full Payment or Installment (EMI).

Buyers can select Onsite Pickup or Home Delivery.

Buyers can report damages and request price reduction.

Admin monitors listings, users, payments, and system activity.

This solution reduces middlemen involvement and creates a secure, efficient, and transparent car trading ecosystem.

4. USER ROLES & PERMISSIONS
A. Buyer:

Can Register and Login.

Can Create and Manage Profile.

Can Browse and Search Cars.

Can Filter Cars (Brand, Price, Year, Fuel Type, Location).

Can Add Cars to Favorites.

Can Compare Multiple Cars.

Can Send Enquiries to Sellers.

Can Place Bids (Auction Mode).

Can Choose Payment Option (Full / Installment).

Can Select Delivery Option (Pickup / Home Delivery).

Can Report Damage and Request Price Reduction.

Can View "My Bids", "My Orders", and "My Enquiries".

B. Seller:

Can Register and Login.

Can Create and Manage Profile.

Can Add New Car Listings.

Can Upload Car Images.

Can Enable Auction Mode.

Can View and Manage "My Listings".

Can View Buyer Enquiries.

Can Accept/Reject Bids.

Can Approve Installment Requests.

Can Manage Delivery Requests.

Can Respond to Damage Reports.

Can Mark Car as Sold.

C. Admin:

Can Login to Secure Admin Dashboard.

Can View and Manage Buyers and Sellers.

Can Approve, Edit, or Remove Car Listings.

Can Monitor Bidding Activities.

Can Monitor Payments and Installments.

Can Manage Delivery Status.

Can Block Fraudulent Users or Listings.

Can View Overall Platform Reports.

5. DATABASE STRUCTURE (Schemas)
A. User Schema:

Name (String)

Email (String, Unique)

Password (Hashed)

PhoneNumber (String)

Role (String: 'buyer', 'seller', 'admin')

CreatedAt (Timestamp)

B. Car Schema:

Title (String)

Brand (String)

Model (String)

Year (Number)

Price (Number)

Mileage (Number)

FuelType (String: Petrol/Diesel/Electric)

Transmission (String: Manual/Automatic)

Location (String)

Images (Array of Image URLs)

SellerID (Reference to User)

IsAvailable (Boolean, Default: true)

Additional Fields:

IsAuction (Boolean)

StartingBid (Number)

CurrentHighestBid (Number)

AuctionEndDate (Date)

DeliveryAvailable (Boolean)

DeliveryCharge (Number)

C. Bid Schema:

CarID (Reference to Car)

BuyerID (Reference to User)

BidAmount (Number)

CreatedAt (Timestamp)

D. Enquiry Schema:

CarID (Reference to Car)

BuyerID (Reference to User)

Message (String)

Status (String: 'Sent', 'Responded', 'Closed')

CreatedAt (Timestamp)

E. Payment Schema (Installment System):

CarID (Reference to Car)

BuyerID (Reference to User)

TotalAmount (Number)

DownPayment (Number)

RemainingAmount (Number)

InstallmentMonths (Number)

MonthlyAmount (Number)

PaymentStatus (String: 'Pending', 'Ongoing', 'Completed')

F. Delivery Schema:

CarID (Reference to Car)

BuyerID (Reference to User)

DeliveryType (String: 'Pickup' or 'HomeDelivery')

DeliveryAddress (String)

DeliveryStatus (String: 'Pending', 'Shipped', 'Delivered')

G. Damage Report Schema:

CarID (Reference to Car)

BuyerID (Reference to User)

Description (String)

DamageImages (Array)

RequestedReductionAmount (Number)

Status (String: 'Pending', 'Accepted', 'Rejected', 'Countered')

FinalAgreedPrice (Number)

6. FEATURE WORKFLOW (The "User Journey")

Registration: User selects role (Buyer or Seller) and registers.

Login: User logs into dashboard.

Seller Action:

Adds car listing.

Enables auction (optional).

Buyer Action:

Searches and filters cars.

Views details.

Sends enquiry or places bid.

Purchase Process:

Buyer selects payment method (Full / EMI).

Chooses delivery option.

Damage Handling:

Buyer reports damage (if any).

Seller negotiates price reduction.

Completion:

Payment confirmed.

Delivery completed.

Car marked as sold.

7. API ENDPOINTS (The URL Rules)
Authentication

POST /api/auth/register -> Register Buyer/Seller

POST /api/auth/login -> Login user

Cars

GET /api/cars -> Get list of cars

POST /api/cars -> Seller creates listing

GET /api/cars/:id -> Get car details

PUT /api/cars/:id -> Update car (Seller/Admin)

DELETE /api/cars/:id -> Delete car (Admin only)

Bidding

POST /api/bids -> Buyer places bid

GET /api/bids/:carId -> View bids

Enquiries

POST /api/enquiries -> Send enquiry

GET /api/enquiries/seller -> Seller view enquiries

Payments

POST /api/payments -> Create payment/EMI

GET /api/payments/user -> View payment status

Delivery

POST /api/delivery -> Request delivery

PUT /api/delivery/:id -> Update delivery status

Damage Reports

POST /api/damage -> Submit damage report

PUT /api/damage/:id -> Seller response
